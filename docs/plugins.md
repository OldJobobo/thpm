# Plugin contract

This is a maintainer reference for built-in integrations. Users can inspect the current list with `thpm list`, check problems with `thpm doctor`, and enable an integration with `thpm enable <id>`. Asset names such as `zed.json` or `gtk.css` refer to files supplied by the active Omarchy theme.

Plugins are records in `src/thpm/registry.py` and adapters in `src/thpm/integrations.py`. A plugin may consume an Omarchy-rendered THPM template, a theme-provided optional asset, or perform a guarded external action. Every adapter reports an explicit `applied`, `unchanged`, `skipped`, or `failed` outcome; an empty change list is never treated as evidence that work succeeded. Reload commands and restart notices run only after managed content changes, so a no-op reconciliation does not probe inactive applications or emit false action requirements. Conditional compatibility integrations also report whether the active theme makes them applicable.

Rules:

- Read colors only from the active Omarchy 4 `colors.toml` contract.
- Do not write files owned by an Omarchy-native integration.
- Preserve user-owned content; use a clearly delimited managed block when editing a shared file.
- Treat a missing optional application as unavailable. When an enabled asset-only integration loses its theme asset, relinquish its managed output and restore the displaced file or application default.
- Reload only the application the adapter owns, bound the command with a timeout, and report nonzero exits.
- Add behavioral tests for paths, generated files, and preservation behavior.

Template names start with `thpm-` and end in `.tpl`. Omarchy renders each into the active theme without the `.tpl` suffix. An adapter then atomically installs that generated output where the application expects it.

The Discord integrations are mutually exclusive. `discord` prefers a theme-provided `vencord.theme.css` and otherwise uses the semantic-palette template. `discord-system24` follows the same pattern with `vencord-system24.theme.css` and its generated System24 fallback. Both install the selected output as `vencord.theme.css` in existing supported client theme directories.

The Zellij adapter generates a complete `thpm-current` theme from the active semantic `colors.toml` palette and prefers a theme-provided `zellij.kdl` as an authored override. It writes the result to Zellij's configured theme directory, selects it in `config.kdl`, and removes the delimited inline block used by pre-1.0 THPM. After changing the external theme, THPM waits for a strictly newer wall-clock second when necessary and atomically rewrites the selected `config.kdl`, ensuring Zellij's polling config watcher reparses the completed theme and updates running sessions without leaving future-dated configuration files. The adapter honors `ZELLIJ_CONFIG_FILE` and `ZELLIJ_CONFIG_DIR` when a custom config declares an absolute root-level `theme_dir`; relative theme directories and custom configs without that declaration are rejected because Zellij resolves them inconsistently between startup and watcher reload. Per-invocation `--config` and `--config-dir` flags cannot be discovered by a persistent theme hook. When neither palette nor authored asset is available—or when the integration is disabled—THPM restores the previously selected theme and any file displaced at `thpm.kdl`. Targets changed outside THPM and untracked legacy targets are preserved.

The GTK compatibility integration synchronizes an active-theme `gtk.css` into THPM-owned GTK 3 and GTK 4 stylesheets and inserts delimited imports into user CSS. It removes only those managed files and blocks when the next theme does not request GTK CSS or the integration is disabled.

Branding, Typora, SwayNC, and cliamp are asset-only integrations. Before their first takeover, THPM records whether the destination existed and preserves its contents. If a later theme omits the asset—or the integration is disabled or THPM is uninstalled—THPM restores that prior file or removes its own destination so the application can use its default. Branding tracks `about.txt` and `screensaver.txt` independently. A destination edited outside THPM after installation is preserved rather than overwritten during cleanup. Restoring SwayNC colors also triggers its supported CSS reload.

Windsurf support is retired and no longer appears in the active integration registry. The editor was replaced by Devin Desktop, whose command, profile, and extension lifecycle no longer match the former Windsurf contract. Reconciliation and uninstall retain guarded legacy cleanup for THPM's old `.windsurf/extensions/local.omarchy-theme/themes/omarchy.json` destination; unknown and user-modified files remain preserved.

The persisted `zed-extra` integration is presented as **Zed authored theme**. It prefers `zed.json`, falls back to `aether.zed.json`, and validates a regular non-symlink UTF-8 JSON file no larger than 1 MiB. The root must contain exactly one dark or light theme with a style object. THPM preserves the schema, author, appearance, and style while normalizing the package and theme names to **THPM Current**, installed restorably at `~/.config/zed/themes/thpm-current.json`. The former `omarchy.json` destination is migrated only through restoration metadata or a positive legacy-content match; unknown and user-modified files are preserved. THPM never modifies `aether.json`, `omazed.json`, or Omazed hooks.

Run `thpm enable zed-extra` to persistently synchronize authored Zed themes after theme changes. Enabling it through the CLI, TUI, or graphical manager also performs the one-time settings operation. `thpm zed setup` exposes only that direct installation and settings-selection step; it does not persistently enable synchronization. The settings operation backs up existing Zed settings once under THPM state and uses a token-aware JSONC edit to select **THPM Current** while preserving comments and keys outside the replaced theme value. Theme hooks never rewrite settings. `thpm zed status` reports source precedence, synchronization, the selected string or light/dark theme, and Omazed command/output availability. Omazed remains an independently owned generated fallback; when no authored source exists, THPM reports that the user may select **Omazed** rather than claiming an automatic switch.

Generated and hybrid integrations use the same displaced-file tracking. Disabling or uninstalling one restores its previous destination and removes its rendered `thpm-*` output; browser cleanup also removes only THPM's delimited `userChrome.css` import. For installations upgraded from versions without restoration metadata, THPM removes a legacy destination only when its contents positively match a current generated output or a locally installed theme asset. Unknown files are preserved, and each legacy path is checked only once.

The local editor compatibility integration handles `local.*` descriptors backed by `vscode-extension/`. It validates that the package is a data-only theme extension, verifies descriptor/manifest identity and the contributed label, builds a deterministic temporary VSIX, and installs it only when its source hash changed or the extension is absent. Executable extensions, arbitrary contributions, symlinks, unsupported files, and prebuilt VSIX bundles are rejected.

Firefox and Zen require an initialized default browser profile, prefer their theme-provided CSS before generated CSS, and report both the managed stylesheet and `userChrome.css` import. Superfile and Cava likewise prefer their declared theme assets before generated fallbacks. Discord requires a supported client theme directory, and Steam requires the steam-adwaita installer. The dock stylesheet has no supported live reload; THPM reports that nwg-dock-hyprland must be restarted instead of claiming a reload occurred.
